# هيكل مشروع Mandour Coffee

## الملفات التي نعدّلها

- `assets/public/index.html` — هيكل الشاشة ونصوصها وربط ملفات الواجهة.
- `assets/public/css/app.css` — تنسيقات التطبيق وألوانه وتخطيط الشاشات.
- `assets/public/js/app.js` — منطق التطبيق، التخزين المحلي، الفواتير، العملاء، الشيكات والبحث.
- `assets/audio/paid-checks.m4a` — المقطع الصوتي الأول الذي أرسله المستخدم.
- `assets/audio/paid-checks-second.m4a` — المقطع الصوتي الثاني الذي أرسله المستخدم.
- `android-src/MainActivity.java` — جسر Android للنسخ الاحتياطي ومشاركة الإيصالات وتشغيل الصوتين.
- `.github/workflows/build.yml` — إعداد بناء Android على GitHub Actions.

## تتابع صوت اكتمال السداد

تشغيل الصوت مرتبط بدخول شاشة الشيكات مع وجود شيك واحد على الأقل وعدم وجود أي مبلغ متبقٍ. يرسل JavaScript مفتاحًا ثابتًا للجسر الأصلي؛ المفتاح يمنع إعادة تشغيل الصوت بسبب إعادة رسم القائمة. يشغل Android الملف الأول، ينتظر ثانيتين بعد انتهائه، ثم يشغل الملف الثاني. مغادرة شاشة الشيكات توقف المشغل وتلغي أي مؤقت قيد الانتظار.

الأصلان الصوتيان محفوظان منفصلين بصيغة M4A؛ لا يتضمن التطبيق ملفات الفيديو الأصلية. يتم نسخ الصوت إلى مجلد cache عند الحاجة فقط لتشغيله، وليس في كل مرة تُفتح فيها الشاشة.

## الملفات المولدة

`www/` هو مجلد الويب الذي يقرأه Capacitor عند المزامنة. أما `android/` فيحوي مشروع Android المولّد والمزامَن. لا نحرّر ملفات الواجهة داخلهما يدويًا؛ نعدّل الملفات المصدر المذكورة أعلاه ثم نشغّل `npx cap sync android`.

## فحوص قبل التسليم

1. `node --check assets/public/js/app.js`
2. `git diff --check`
3. بناء `assembleDebug` وفحص رقم الإصدار والتوقيع.
4. التأكد من وجود ملفات M4A داخل APK وخلوه من MP4.
