# هيكل مشروع مندوركوف

## الملفات التي نعدّلها

- `assets/public/index.html` — هيكل الشاشة ونصوصها وربط ملفات الواجهة.
- `assets/public/css/tokens.css` — ألوان ومسافات التصميم المشتركة.
- `assets/public/css/app.css` — التنسيقات الأساسية للمكونات والشاشات.
- `assets/public/css/cashier.css` — تدفق الطلبات والطاولات وتحسينات الهاتف.
- `assets/public/css/dark-theme.css` — طبقة الثيم الداكن.
- `assets/public/js/app.js` — منطق التطبيق، التخزين المحلي، الفواتير، العملاء، الشيكات والبحث.
- `assets/mandour-app-icon.png` — الصورة المعتمدة لأيقونة الويب وشعار التطبيق.
- `assets/mandour-app-icon-foreground.png` — مصدر توليد طبقة Adaptive Icon من الصورة المعتمدة.
- `android-res/mipmap-*` — أيقونات Android بأحجام كثافات الشاشة المختلفة.
- `android-res/mipmap-anydpi-v26/` و`android-res/values/ic_launcher_background.xml` — تعريف الطبقات ولون خلفية Adaptive Icon.
- `assets/audio/Ayano.mp3` — المقطع الصوتي الموجود في ملف المستخدم: `Ayano.mp3`.
- `assets/audio/notification-glass.mp3` — جرس الإشعارات الزجاجي، يُنسخ إلى `res/raw` لقناة Android.
- `assets/audio/customer-name-reminder.mp3` — تنبيه الاسم عند حفظ أصناف دون اسم عميل.
- `assets/audio/order-wood.mp3` — نغمة اختيار صنف من قائمة المشروبات.
- `android-src/MainActivity.java` — جسر Android للنسخ الاحتياطي ومشاركة الإيصالات وتشغيل المقطع الصوتي.
- `.github/workflows/build.yml` — إعداد بناء Android على GitHub Actions.

## تتابع صوت اكتمال السداد

تشغيل الصوت مرتبط بدخول شاشة الشيكات مع وجود شيك واحد على الأقل وعدم وجود أي مبلغ متبقٍ. يرسل JavaScript مفتاحًا ثابتًا للجسر الأصلي؛ المفتاح يمنع إعادة تشغيل الصوت بسبب إعادة رسم القائمة. يشغل Android المقطع الصوتي الأول مرة واحدة، ومغادرة شاشة الشيكات توقف المشغل.

المقطع الصوتي محفوظ بصيغة M4A؛ لا يتضمن التطبيق ملفات الفيديو الأصلية أو صورًا غير مستخدمة. يتم نسخ الصوت إلى مجلد cache عند الحاجة فقط لتشغيله، وليس في كل مرة تُفتح فيها الشاشة.

## الملفات المولدة

`www/` هو مجلد الويب الذي يقرأه Capacitor عند المزامنة. أما `android/` فيحوي مشروع Android المولّد والمزامَن. لا نحرّر ملفات الواجهة داخلهما يدويًا؛ نعدّل الملفات المصدر المذكورة أعلاه ثم نشغّل `npx cap sync android`.

## فحوص قبل التسليم

1. `node --check assets/public/js/app.js`
2. `git diff --check`
3. معاينة هاتف: اختر طاولة، احفظ مسودة، غيّر وجهتها مع رفض/قبول النقل، ثم اعتمدها.
4. اختبار دمج نسخة تحتوي سجلات مكررة ومسودة وبيانات مختلفة مع نسخة موجودة.
5. بناء `assembleDebug` وفحص رقم الإصدار والتوقيع.
6. التأكد من وجود ملفات M4A داخل APK وخلوه من MP4.


## تدفق الطاولات وحماية البيانات

- شريط الطاولات وعداد الزيادة/النقصان مصدرهما `renderTableNumberSelector()` و`normalizeTableName()` في `assets/public/js/app.js`، مع قيود صريحة على ١–٥.
- المسودة ووجهة الحساب تحفظان في `data.pendingOrder`; قبل نقلها إلى حساب أو طاولة مختلفة يظهر تأكيد. رصيف التأكيد في `assets/public/index.html` خارج `main` حتى لا يحوله انتقال `.view` إلى عنصر داخل الصفحة.
- استيراد النسخة يتعامل مع العملاء والتوليفات والفواتير المحذوفة والإشعارات والمخزون والولاء وبيانات الموظف وQR والمسودة. عند تعارض مسودة محلية بأصناف مع مسودة مستوردة، يحتفظ التطبيق بالطلب المحلي الجاري.
- يحفظ جسر Android النسخ الجديدة مؤقتًا أولًا ثم يبدل الاسم إلى `Ayanoo.json` بعد نجاح الكتابة، ويعيد الاسم السابق إذا فشل الاستبدال.
- تتوزع التنسيقات على `tokens.css` للرموز المشتركة و`app.css` للمكونات الأساسية و`cashier.css` لتدفق الكاشير والهاتف و`dark-theme.css` لطبقة الوضع الداكن.

## نتائج اختبار بيئة التطوير

اختُبرت الواجهة في Chromium بعرض هاتف ٣٦٠–٣٩٠ بكسل، مع بيانات اختبار داخل Local Storage مؤقتة فقط: التنقل بين الشاشات، الثيمين، البحث الفارغ والنتيجة غير المطابقة، الطاولات ١–٥ والحدود، حساب مشغول، حفظ المسودة واستعادتها، رفض/قبول نقل الوجهة، تسجيل الحساب، حساب سعر وزن ومضاف محوج، ودمج النسخة. أُجري اختبار فشل تخزين اصطناعي منفصل وتأكد رجوع الفاتورة/الولاء وبقاء مسودة الطلب. لا تعتبر هذه اختبارات تشغيل على جهاز Android حقيقي؛ يلزم أيضًا نجاح بناء APK وفحص توقيعه قبل التسليم.
